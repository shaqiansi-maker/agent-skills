# AI 产品研究 Skill 使用说明

这个 Skill 用于研究一个或多个 AI 产品，也可以只研究多个产品共同体现的一项能力，例如 Agent、工作流、记忆、MCP、权限、审计、支付或商业化。

它不会默认把所有产品做成完整竞品矩阵，而会先判断你真正想解决的问题。

## 最简单的使用方式

通常一句话就可以开始：

```text
请使用 ai-product-research，分析 Carrier 的产品定位、能力构成和后续演进，并验证它的 MCP 能力。
```

```text
请使用 ai-product-research，研究 Carrier、Dify 和扣子在 MCP、权限和审计方面的共同设计与差异，不需要完整竞品分析。
```

```text
请使用 ai-product-research，结合当前项目判断这项能力是否值得进入下一版。
```

如果请求已经明确，Agent 应直接复述范围并开始，不要求填写问卷。只有不同理解会显著改变范围或结论时，它才会问一个关键问题。

## 可以完成什么

- 单个 AI 产品深度分析；
- 多个产品的竞品比较；
- 跨产品能力专题研究；
- API、MCP、Agent、权限和数据边界分析；
- 授权范围内的功能实测；
- 技术接入、选型和采购评估；
- 结合目标项目形成产品与架构建议；
- 无目标项目时沉淀通用能力模型和测试方法。

## 是否必须提供项目

不必须。

有目标项目时，Agent 会优先读取或询问项目定位、阶段、已构建能力和约束，再形成 `do_now / test_first / do_later / do_not_do / observe` 决策。

没有项目时，Agent 会输出产品事实、能力模型、设计原则、测试方法、适用条件和未来采用标准，不会虚构项目优先级。

## 链接、截图和登录

优先使用可核验的公开资料。公开资料不足时，Agent 会明确判断：

- 不需要补充材料；
- 补充会提高质量但不阻塞；
- 必须提供指定截图、登录观察或测试授权，否则关键结论不能成立。

用户提供登录或测试授权后，Agent 仍应说明测试环境、允许动作、停止条件和清理方式。测试成功只证明指定版本、账户、环境和任务下的结果。

## 功能验证由谁执行

默认不是让用户照着清单逐项测试。获得必要授权后，Agent 应自行建立测试背景、任务集、数据、工具、评判方法和证据记录，在允许范围内执行、复核并清理。

只有以下内容需要用户介入：

- 登录、验证码或只有用户能访问的页面；
- 只有用户掌握的项目事实或业务判断；
- 写入、发布、购买、删除等外部副作用授权；
- 用户明确表示希望亲自体验或主导验证。

用户主测时，Agent 提供测试步骤、观察点和证据要求，并负责解释结果边界。

## 你会得到什么

结果首先给出简单直接的结论，再按任务深度提供：

- 产品事实与证据；
- 能力模型与实现模式；
- 竞品或样本之间的关键差异；
- 功能测试结果与证据边界；
- 产品、架构、商业和采用影响；
- 项目行动建议或无项目条件下的适用原则；
- 尚未验证的问题和下一步测试。

## 跨平台核心

只有一份核心 Skill：

```text
ai-product-research/
  SKILL.md
  references/
  agents/        # 可选平台元数据
```

不同平台只处理安装目录、发现方式和调用语法。不要为 Codex、Claude、Kiro 或其他 Agent 复制不同版本的 `SKILL.md`。

跨平台兼容表示研究方法和文件结构可复用，不表示所有宿主都具备相同的联网、浏览器、MCP、命令、文件和写入权限。

## 跨平台安装

分享时发送整个 `ai-product-research` 文件夹，或使用仓库中的版本化压缩包。不要只发送 `SKILL.md`，否则会缺少证据、测试、项目映射和报告规则。

### Codex

放入：

```text
~/.codex/skills/ai-product-research/
```

调用：

```text
使用 $ai-product-research 分析……
```

### Kiro

个人范围：

```text
~/.kiro/skills/ai-product-research/
```

项目范围：

```text
<project>/.kiro/skills/ai-product-research/
```

可通过自然语言或 `/ai-product-research` 调用。若自定义 Agent 不继承默认 Skills，需要把该 Skill 加入 Agent 的 resources。

### Claude Code

个人范围：

```text
~/.claude/skills/ai-product-research/
```

项目范围：

```text
<project>/.claude/skills/ai-product-research/
```

可以直接用自然语言点名该 Skill。Claude.ai 或 Claude API 若已开放 Skills 导入，可上传仓库中的版本化 ZIP；具体入口和权限以平台当前文档为准。

### 其他 Agent

原生支持 Agent Skills 的平台，将整个文件夹放入平台声明的 Skills 目录。

不原生支持时：

1. 把 `SKILL.md` 作为自定义 Agent 或系统指令；
2. 允许 Agent 按需读取 `references/`；
3. 为网页访问、附件、浏览器、API/MCP 或文件写入配置相应权限；
4. 用上面的自然语言示例发起任务。

`agents/openai.yaml` 只是可选的 OpenAI/Codex 界面元数据，不改变跨平台核心方法。

WorkBuddy 或其他平台若没有原生 Skills 目录，也使用上述通用方式；只有平台存在不可避免的特殊格式时才增加薄适配，不复制研究正文。

## 宿主能力检查

首次运行时，Agent 应检查本次任务实际可用的能力：

| 能力 | 不可用时的处理 |
| --- | --- |
| 读取 `references/` | 将必要参考内容加入 Agent 上下文，否则不能声称完整使用本 Skill |
| 网页或浏览器访问 | 使用用户材料并降低当前性和实测结论 |
| 项目文件读取 | 请求最低必要项目信息，或转为无项目研究 |
| API/MCP 调用 | 只确认公开接口主张，不能确认真实执行 |
| 命令或自动化测试 | 改为浏览器、人工辅助或用户主测 |
| 文件写入 | 在对话中交付，不声称已生成文件 |
| 外部系统写入 | 必须另行授权；没有授权时只读研究 |

平台升级后只更新安装或调用适配。研究、证据和验证规则仍维护在唯一核心 Skill 中。
