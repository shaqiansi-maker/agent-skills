## 何时需要实测

只有同时满足以下条件时才进入实测：

- 主张会影响重要的产品、架构、采购或接入决策；
- 公开资料不能充分证明它；
- 当前环境允许形成有意义的观察；
- 用户已授权所需账户、凭据和外部动作；
- 风险、成本和清理方式可控。

若只能运行厂商 Demo，必须将结论限制为 Demo 环境，不推广为生产能力。

## 测试契约

测试前记录：

```markdown
### 测试契约
- 待验证主张：
- 产品、版本和入口：
- 账户、角色和作用域：
- 测试环境与数据：
- 参与方式：agent_led / collaborative / user_led
- 允许的读取动作：
- 允许的写入或外部副作用：
- 明确禁止：
- 成功标准：
- 停止条件：
- 证据保存方式：
- 清理方式：
```

没有授权时只做只读观察。获得授权后默认由 Agent 在授权范围内建立并执行测试，不要求用户逐步代操作。发现测试范围、权限、成本或副作用需要扩大时，停止并重新确认。

用例状态：`pass / partial / fail / blocked / not_run`。

`pass` 只表示当前用例满足预期，不等于整项能力或产品通过。

## 最小测试集

根据研究主张选择，不为形式测试无关场景：

1. **正常路径**：代表性任务能否完成；
2. **边界输入**：空值、超长、特殊格式、重复请求或不存在对象；
3. **权限与作用域**：不同角色、本人/他人、项目/空间边界；
4. **失败与超时**：依赖失败、服务不可用、返回不完整；
5. **恢复**：重试、幂等、撤回、回滚、历史记录和人工接管；
6. **可追溯性**：调用编号、操作者、输入输出、时间、版本和审计检索；
7. **清理**：测试数据、临时服务、凭据、缓存和本地配置。

## UI 产品

记录：

- 用户从哪里进入；
- 关键输入与选择；
- 平台是否解释将发生什么；
- 加载、等待、失败和取消；
- 输出、状态和下一步动作；
- 用户修改后是否自动重跑；
- 是否有历史、版本、撤回和删除；
- 是否产生外部副作用。

证据优先包含完整页面、关键操作前后状态、错误提示和时间信息。若工具允许，保存操作 Trace、网络请求和控制台错误；不要只截成功终态。

## API 和 MCP

先检查发现和契约，再检查行为：

- 工具、资源或端点能否发现；
- 名称、用途和作用域是否清楚；
- 输入 Schema、必填项、枚举和限制；
- 输出字段、类型、错误结构和分页；
- 身份、空间、项目和角色如何绑定；
- 读写、副作用和审批是否明确；
- 调用编号、日志和审计能否闭环；
- 无权限、不存在、空结果和服务错误能否区分；
- 并发、重复调用、超时和重试如何处理。

调用结果应记录工具名、实际参数、结构化返回、调用编号、数据来源和环境。若文本返回与结构化返回字段不一致，单独记录。

## Agent 和工作流

若主张涉及生成质量、记忆、检索、规划、工具选择或输出波动，同时使用 [AI 能力评测](ai-capability-evaluation.md)，不要只按确定性功能用例判断。

区分：

- 模型生成了计划；
- 系统执行了工具；
- 外部系统发生了变化；
- 系统校验了结果；
- 结果写回了权威对象；
- 失败后能够恢复或人工接管。

不要因为聊天中声称“已完成”就认定任务完成。需要核对工具记录、目标系统事实或可验证产物。

代表性任务集应包含：正常任务、含糊任务、缺少信息、工具失败、危险动作、用户修改和恢复任务。评价准确性、完成度、边界遵守、解释性、恢复能力和成本。单次成功不能证明稳定性；测试次数和任务变化应由待验证主张、风险与输出波动决定。

## 权限与安全边界

本 Skill 不是渗透测试工具。只在明确授权和隔离环境内检查：

- 当前凭据能看到什么；
- 工具是否把身份和作用域作为服务端约束；
- 输入中能否任意指定他人、空间或项目；
- 写操作是否需要审批或额外授权；
- 日志是否泄露凭据或敏感数据；
- 撤销凭据后访问是否停止。

没有第二账户、管理员后台或审计检索权限时，不声称已证明跨用户隔离或审计闭环。

## 商业与生产成熟度验证

功能可运行不等于商业可用。生产成熟度还可能需要：

- SLA、支持与升级策略；
- 部署、数据隔离与退出机制；
- 计费单位、实施费和最低合同；
- 上线客户、验收案例和真实负载；
- 故障、越权、误执行和数据泄露责任；
- 合规、采购和安全评审材料。

拿不到这些证据时，将商业或生产成熟度标记为 `unverified`，不要由 Demo 反推。

## 清理与结束

结束前列出：

- 已删除的测试数据和临时文件；
- 已停止的本地服务；
- 已移除的 Agent/MCP 配置；
- 已撤销或仍有效的凭据；
- 为报告保留的去敏证据；
- 因调试需要暂留的内容、位置和清理责任。

无法自动清理时，给用户准确步骤并明确遗留风险。
